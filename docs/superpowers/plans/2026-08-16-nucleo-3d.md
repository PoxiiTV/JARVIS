# Núcleo JARVIS 3D — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el núcleo central se lea como una esfera holográfica 3D (orb + órbitas inclinadas + bloom), no como un círculo CSS con partículas alrededor.

**Architecture:** El HUD ya monta Three.js r128 en `#hud`. No se cambia de motor. Se extrae el reactor a `hud-three.js`, se sustituye la esfera plana (`MeshBasicMaterial` + sprites) por un núcleo con volumen (shader fresnel + luz interior), se añaden dos elipses orbitales inclinadas y bloom, y se quita el cromado 2D de `#core-label` para que deje de aplastar la ilusión.

**Tech Stack:** Three.js (subir a r160 ESM local) · EffectComposer + UnrealBloomPass · FastAPI `/static` · Electron kiosco (sin React, sin Spline)

**Spec:** este documento. Decisiones de enfoque: Opción A (abajo). Pendiente de OK del señor antes de tocar código.

## Diagnóstico — por qué ahora se ve 2D

Ya hay 3D. `app/static/index.html` carga Three.js desde CDN (`r128`) e `initThree()` pinta el reactor. El problema no es «falta Three», es **cómo está construido el núcleo**:

| Capa | Qué hace hoy | Por qué aplasta el 3D |
|------|----------------|------------------------|
| `coreSphere` | `SphereGeometry(16)` + `MeshBasicMaterial` | Sin luz, sin fresnel: es un disco de color uniforme |
| `coreSprite` + `coreGlow` | Sprites billboard | Siempre miran a cámara → halo plano |
| `#core-label` | Círculo HTML 92px con borde y `::before` girando | Tapa el centro 3D con un badge 2D |
| `RingGeometry` / torus | Aros casi coplanares | Poco eje Z; no leen como órbitas atómicas |
| `setPixelRatio(1)` + `antialias: false` | Rendimiento | El borde de la esfera se ve pixelado |
| Bloom | No hay | La referencia vive del glow volumétrico |

La captura de referencia (orb cian, texto JARVIS, elipses inclinadas, arco teal, anillo de puntos) **no pide otro producto**. Pide que el reactor actual deje de ser un disco y pase a ser un átomo holográfico.

Reglas que este plan **no rompe** (plan Iron Man):

- El 3D no se apaga por FPS. No vuelve «Modo 3D desactivado».
- En móvil (`isLite`) se degradan capas, no se apaga WebGL.
- Estados: `idle` / `thinking` / `speaking` siguen pintando color y pulso.
- `visibilitychange` sigue pausando el `raf`.

## Tres enfoques (elegir uno)

### A — Subir el Three que ya tenemos *(recomendado)*

Misma escena, mismo `#hud`, mismo ratón. Cambiar el núcleo y las órbitas. Extraer a `hud-three.js` (ya previsto en Fase 3.1 del plan Iron Man).

- **Pros:** encaja en el HUD; estados actuales se reutilizan; peso controlado; offline si vendorizamos.
- **Contras:** bloom cuesta GPU; hay que pasar de UMD CDN a ESM (o copiar el pass a mano).
- **Por qué A:** la captura es exactamente este lenguaje visual. No hace falta otro motor.

### B — Escena hecha en Spline / Blender (GLTF)

Diseñar el orb fuera, cargarlo con `GLTFLoader`.

- **Pros:** look de agencia si se itera en el editor.
- **Contras:** toolchain extra; colorear speaking/thinking es un lío (hay que exponer materiales); un `.glb` se desincroniza del CSS; no hay React/R3F en este repo.
- **No.** Exceso para un núcleo que tiene que reaccionar a clases del DOM.

### C — CSS 3D / canvas 2D fingiendo profundidad

`transform: rotateX` en elipses, radial-gradient en el centro.

- **Pros:** cero WebGL.
- **Contras:** no es la captura; el volumen de la esfera no existe; ya tenemos Three.
- **No.** Retroceder.

**Decisión por defecto de este plan: A.** Si el señor elige B o C, se reescribe el plan; no se implementa A a medias.

## Diseño cerrado (Opción A)

### Qué se ve

1. **Esfera con volumen** — shader propio (no `MeshBasicMaterial`):
   - núcleo blanco-cian en el centro
   - fresnel en el borde (el halo que delata que es una bola)
   - ruido suave de energía
   - `PointLight` dentro, para que los aros tengan cara de luz
2. **Dos elipses orbitales** inclinadas ±18° (TubeGeometry fino, blending aditivo). Giran en ejes distintos. Esto es la firma de la captura.
3. **Anillos concéntricos de puntos** — los `rings` actuales se quedan, más densos cerca del núcleo.
4. **Un arco teal** (~90° de circunferencia) sobre el anillo medio. Ya hay `arcs`; se ajusta radio/grosor para parecerse a la captura, no se inventa un sistema nuevo.
5. **Perímetro de puntos** — el anillo hexagonal actual puede pasar a puntos redondos (la captura no tiene hexágonos de panel). En `isLite` se oculta.
6. **Texto JARVIS** — HTML encima, **sin** círculo, borde ni spinner. Solo la palabra + `text-shadow`. El 3D se ve alrededor y a través. No CSS2DRenderer (YAGNI).
7. **Bloom** — `UnrealBloomPass` suave. En `isLite`: bloom off, shader más barato, menos puntos. El 3D sigue encendido.

### Qué no entra (YAGNI)

- React / R3F / Babylon / Spline
- Modelo GLTF
- Física, sombras reales, environment map de habitación
- Interacción de click en la esfera
- Partículas que salen disparadas al hablar (el pulso de escala + color basta)
- Rediseñar paneles laterales

`index.html` tiene ~2450 líneas. Extraer Three **antes** de reescribir el núcleo, para no minar el archivo (misma razón que Task 3.1 del plan Iron Man). Aquí se extrae y se mejora en el mismo ciclo, no se extrae “idéntico” y luego se tira.

### Datos / estados

El loop `tick` sigue leyendo el DOM, no un bus nuevo:

```
#hud-ui.thinking  → color 0x33e0ff, pulso medio, órbitas más rápidas
speaking === true → color 0x00ffb3, pulso fuerte
idle              → color 0x00d4ff, pulso lento
document.hidden   → pause raf
```

`speaking` sigue siendo la global que ya setea el chat. No se duplica.

### Rendimiento

- `pixelRatio = min(devicePixelRatio, 1.5)` en desktop; `1` en `isLite`
- `antialias: true` solo desktop
- Bloom: `strength` 0.6–0.9, `radius` ~0.4, `threshold` ~0.7 (ajustar a ojo; si se ve leche blanca, bajar strength)
- Pausar en pestaña oculta (ya existe)
- Si WebGL falla: `catch` actual, HUD sin canvas, log warn. **No** mensaje «Modo 3D desactivado» en el chat.

### Three r160 vs r128

El bloom de `examples/jsm` no encaja limpio con el UMD r128 del CDN. Pasar a **r160 ESM vendorizado** en `/static/vendor/three/`. Importmap en `index.html`:

```html
<script type="importmap">
{
  "imports": {
    "three": "/static/vendor/three/three.module.js",
    "three/addons/": "/static/vendor/three/addons/"
  }
}
</script>
<script type="module" src="/static/hud-three.js?v=orb1"></script>
```

Electron carga `http://127.0.0.1:8080` (mismo origen): importmap funciona. Sin red externa después del vendor.

1. El módulo `hud-three.js` **no** lee `speaking` en el closure de carga. Lo lee **dentro de `tick`**: `window.speaking === true` (el inline ya hace `let speaking`; en browser eso es global de script clásico, no de module).

```js

```

El inline asigna `speaking = true/false` como ahora. Añadir en el inline, junto a `let speaking`:

```js
window.speaking = false;
```

y cada `speaking = …` existente pasa a actualizar ambos, **o** se sustituye por un setter único. Mínimo invasivo: al final de cada asignación a `speaking`, `window.speaking = speaking`. Mejor: una función `setSpeaking` si ya existe — usarla.

Comprobar en `index.html` si ya hay `setSpeaking`. Si sí, ahí se pone `window.speaking = on`.

### Task 3: Esfera con volumen (el cambio que se nota)

**Files:**
- Modify: `app/static/hud-three.js` (sustituir `coreSphere` + sprites)
- Modify: `app/static/hud.css` (`#core-label`)

- [ ] **Step 1: Shader del núcleo**

Sustituir `MeshBasicMaterial` por `ShaderMaterial`:

```js
const coreUniforms = {
  uTime: { value: 0 },
  uColor: { value: new THREE.Color(0x00d4ff) },
  uPulse: { value: 1 },
};
const coreSphere = new THREE.Mesh(
  new THREE.SphereGeometry(28, 64, 64),
  new THREE.ShaderMaterial({
    uniforms: coreUniforms,
    transparent: true,
    depthWrite: false,
    blending: THREE.AdditiveBlending,
    vertexShader: `
      varying vec3 vNormal;
      varying vec3 vView;
      void main() {
        vNormal = normalize(normalMatrix * normal);
        vec4 mv = modelViewMatrix * vec4(position, 1.0);
        vView = normalize(-mv.xyz);
        gl_Position = projectionMatrix * mv;
      }
    `,
    fragmentShader: `
      uniform vec3 uColor;
      uniform float uPulse;
      uniform float uTime;
      varying vec3 vNormal;
      varying vec3 vView;
      void main() {
        float fresnel = pow(1.0 - max(dot(vNormal, vView), 0.0), 2.2);
        float core = 0.35 + 0.25 * sin(uTime * 2.0);
        vec3 col = uColor * (core * uPulse + fresnel * 1.4);
        float alpha = 0.55 + fresnel * 0.45;
        gl_FragColor = vec4(col, alpha);
      }
    `,
  })
);
```

Radio 28 (antes 16): la bola se lee más. Sprites de glow: **uno** solo, más suave, no dos billboards enormes que comen la esfera. `PointLight` en `(0,0,0)` color cian, intensidad baja, para torus/arcs.

En `tick`: `coreUniforms.uTime.value = t * 0.001`; `uPulse` = el `pulse` actual; `uColor` = el lerp actual.

- [ ] **Step 1: Dos elipses inclinadas**

Sustituir (o complementar) `torus1`/`torus2` wireframe por tubos:

```js
function orbit(radius, tube, tiltX, tiltZ, color) {
  const curve = new THREE.EllipseCurve(0, 0, radius, radius * 0.38, 0, Math.PI * 2, false, 0);
  const pts = curve.getPoints(128).map(p => new THREE.Vector3(p.x, p.y, 0));
  const geo = new THREE.TubeGeometry(new THREE.CatmullRomCurve3(pts, true), 128, tube, 8, true);
  const mesh = new THREE.Mesh(geo, new THREE.MeshBasicMaterial({
    color, transparent: true, opacity: 0.85,
    blending: THREE.AdditiveBlending, depthWrite: false,
  }));
  mesh.rotation.x = tiltX;
  mesh.rotation.z = tiltZ;
  scene.add(mesh);
  return mesh;
}
const orbitA = orbit(72, 0.55,  0.32,  0.15, 0x00e5ff);
const orbitB = orbit(72, 0.55, -0.32, -0.20, 0x00ffd0);
```

En `tick`: `orbitA.rotation.y += speakingNow || thinking ? 0.012 : 0.004` (y `orbitB` al revés). Eso es el “átomo vivo”.
